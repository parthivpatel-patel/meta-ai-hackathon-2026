# Three-minute FORGE 4.0 demonstration

Use the reviewed v4 local/private preview until the owner approves an actual release. The existing public deployment does not automatically contain this UI. Prepare a recording and exported reports as the fallback for free-host cold starts or restart loss.

## 0:00–0:25 — The problem and the case

Open the case lobby. Say: “FORGE investigates equipment problems by testing explanations against evidence. All measurements in this demonstration are synthetic.” Choose **An unusual pressure reading**, then **Open investigation**. The overview identifies unusual pressure measurements without claiming they prove a failure.

## 0:25–0:55 — Evidence rather than a generated story

Choose **Examine the evidence**. Inspect pressure at a selected minute, then switch to another signal to show independent scales and real units. Explain: “A sensor error, a process change or both could explain an unusual reading.” Briefly open the thermal image. State that calibrated thermal and vibration records are contextual evidence; this display is not proof of native model visual reasoning.

## 0:55–1:25 — Competing causes and the model boundary

Choose **Prepare possible causes**. Show that multiple candidates remain open and rank is not a probability. Open one candidate. State the actual analysis source. With deterministic mode, say: “This run uses deterministic candidate generation. It is not a genuine Meta inference demonstration.” The prepared Meta adapter can provide structured candidates when separately authorized and verified; it does not control the numerical verifier. Do not claim eligible model use without the retained genuine response and replay evidence required by `MODEL_ACTIVATION.md`.

## 1:25–2:05 — The verified investigation loop

Choose **Choose the next test**. Read the proposed independent reference check, then **Run the next test**. Show that the investigation continues rather than stopping at its first explanation. Choose the next test and run it. Explain: “The numerical engine compares independent observations under controlled interventions. Candidate wording and asserted model confidence cannot force a supported finding.”

## 2:05–2:35 — Findings, contradictions and limits

Results show a process pressure change and a sensor error together. Expand the pressure result to expose numerical before/after reference means and actual replicates. Open the uncertainty disclosure. Say: “The finding is supported within this scripted synthetic model, not established causality in industrial equipment.” For a longer rehearsal, use the incomplete-record case to show explicit refusal to reach a conclusion.

## 2:35–3:00 — Reproducibility

Choose **Prepare the report**. Download the readable report and numerical verification record. Explain that offline replay recomputes the finding without a model endpoint, and hashes support content consistency rather than signed authenticity. End with what was actually demonstrated: competing explanations, controlled tests, independent verification and reproducible evidence.

## Recording and judging evidence

Record the exact branch/commit, screen size, analysis source and case used. Retain the video, HTML/JSON exports, independent replay output and validation summary. A recording of deterministic mode cannot substitute for the competition's eligible Meta model requirement. Keep the real activation blocker explicit; never splice a fixture into a recording and describe it as a real model response.

## Genuine-Meta segment after verified activation

For the final recording, replace the conditional integration explanation with actual evidence only after successful authorized smoke/evaluation. Show the actual source and requested/returned event model identifier, then say: “The Meta model supplied these structured possible causes from the observed evidence. The test selector and numerical verifier are independent.” If the response was retained earlier, explicitly say it is recorded. Use measured request timing and reported usage only when available; do not reuse fixture values. State the actual evaluation sample size and failure/abstention outcomes rather than promising a particular result. Accompany actual model use with the required “Built with Muse Spark Open” attribution and applicable license review.
