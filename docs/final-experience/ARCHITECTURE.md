# Architecture and recovery contract

The existing FastAPI/React modular monolith remains. No model, numerical verifier, experimental selector, report schema or persistence engine was replaced. A single case directory and shared Cases → Machine → Telemetry → Investigation → Experiments → Verification → Reports navigation coordinate the two existing case families. Evidence, Replay and Status / About are directly accessible. Compatibility `/demo?view=investigations`, original stage navigation and Change case actions remain available.

Coupled-pump cases retain the deterministic simulator, operating controls, captured observation window, component inspection, explicit bounded tests, independent findings and v4/v5 export/replay. The retained original cases retain thermal/waveform/equipment context and their sequential engine. Their reference 3D assembly uses the actual case's three available readings; RPM/flow and operating state are missing, so it has no inferred rotor motion or invented coupled telemetry. Geometry is illustrative, not case-calibrated. The library display cursor is an inspector position, not a new numerical analysis window: that engine still verifies its recorded120 measurements.

Active case state remains in its owning component. Hidden workspaces remain mounted and paused; async navigation callbacks cannot redirect another case family. The library's reference machine selection/cursor is lifted into its case workspace and retained across modes. The original case views and schemas remain compatible. No duplicate numerical engine or server service was introduced.

## Browser-local checkpoints

IndexedDB database `forge-recovery`, version1, stores only `machine` and `library` keys in `checkpoints`: at most two latest checkpoints,1 MiB each. Envelope: `forge-browser-checkpoint-1`, `kind`, `saved_at`, `data`. This is browser-local recovery, not durable server storage, encrypted storage, cross-device sync or source authentication. Clearing site data, browser eviction, private browsing or another same-origin script can remove/change it. Export important reports and checkpoints externally.

Machine data contains a bounded recipe, stable selected component, cursor, mode, playback speed and optional canonical public industrial report. Report source/provenance, hypotheses, plan, trials, events and numerical findings remain in that unchanged report. Imported operator telemetry is not autosaved because it has no trusted counterfactual oracle. Playback always restores paused. Prepared model-input downloads, transient previews, graphics preferences and the operator playback log are not fabricated or resurrected; independently recorded experiment history remains in the report.

Library data contains only an admissible public deterministic `Session`, optionally its validated display selection/cursor/mode. Provider records, credentials, private receipts and private-owner cases are not saved. Compatibility checkpoints without inspection preferences can still be numerically recovered. The display defaults are not represented as a recovered historical selection.

Persistence uses a closed envelope, bounds, case/sensor/recipe checks, secret-field/credential-pattern rejection and strict report/proposal top-level projections. Autosave is debounced and paused during operations. At boot, an existing checkpoint is offered explicitly and protected from being overwritten by the initial default case. Save/Export/Import/Discard are explicit actions. A malformed or incompatible stored record is rejected; it does not silently become a new investigation. Storage denial/fullness leaves current analysis usable. Failure to remember a transient server ID cannot turn a successful server action into a misleading retry.

## Independent restoration

Pump restoration first regenerates its bounded synthetic recording and independently reproduces the report through existing v4/v5 handlers. Full canonical equality is required before any existing UI data is replaced. It never calls a model or advances a new trial. A failed/cancelled restore preserves current evidence.

`POST /api/v6/recover` rehydrates only fixed public deterministic library cases. It uses the existing work gate/body/rate/storage bounds. It checks a submitted snapshot against the fixed preset's independently regenerated observations, assets, metadata, rules, selection, existing trials, event sequence and numerical result. It replays only the claimed existing history, with no provider and no extension beyond that snapshot; it does not attest that the historical event really happened. A fresh temporary server ID/version is allocated and all prior evidence/trials and remaining four-test budget are retained. Subsequent selection and execution still require separate explicit actions and optimistic version checks. No client ID overwrites another session. General industrial uploads, model-backed private sessions and arbitrary recipes are not accepted by this route.

Browser JSON spells integral floats as integers. Recovery normalizes that representation only for canonical comparison, while rejecting raw boolean substitutions before Pydantic coercion. It never changes the existing hash/report/verifier contracts. The stored reconstructed state uses the original factory types; completed report identity remains stable because transient server ID/version are not part of that existing report identity. The browser also compares recovered content excluding only transient ID/version before attaching it.

## Meta boundary

The existing private smoke implementation remains adequate and unchanged. The one conditional Phase 7 authorization does not enable public inference, retries, evaluation or follow-up calls. The public interface distinguishes rules, recorded transport fixtures and unattested recorded Meta claims. Public status never infers connectivity from a private smoke. An actual privately verified/recorded-genuine state requires reviewed evidence that this run does not possess. No fabricated genuine fixture or success badge is included.
