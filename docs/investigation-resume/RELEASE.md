Verify whether it is the owner-reported Phase 7 `4e40f41f6f5d777e664eb52b1ffc89a1d615baad`. Confirm that this known-good artifact and its **Rollback** control are retained before proceeding. Do not assume rollback availability from a Git branch.
2. Inspect existing settings without changing them: repository `parthivpatel-patel/meta-ai-hackathon-2026`, Docker runtime, **Free** instance, auto-deploy already off, readiness path `/api/v3/ready`, and the existing configured branch. 4. Choose **Manual Deploy → Deploy a specific commit**. Enter the **full pushed fix SHA** from the handoff and confirm it is accepted for this repository. Deploy that exact commit only after the owner's separate release decision. Do not select latest branch commit, change the configured branch, merge, add a resource or upgrade the plan. 5. Wait for the new deploy to be **Live** and verify its actual SHA. Open `https://forge-judge.onrender.com/api/v3/ready` and `/demo` over external HTTPS. Return to observed simulation and confirm new capture is eligible without replacing that report. Save/refresh/explicitly restore a disposable checkpoint and resume; verify exports/replay and public inference-disabled status. Use disposable data, not destructive session deletion on production.

## Rollback

If acceptance fails, open **Events**, select the **actual prior Live deploy recorded in step 1**, verify its artifact/SHA, and use **Rollback** only if the retained artifact/control is available. Confirm the resulting Live SHA, HTTPS readiness and prior core workflows. Rollback restores code, not lost SQLite records, environment configuration or browser state. If the artifact/control is unavailable, stop for a separate recovery decision; rebuilding a historical commit is not an assumed artifact rollback. Do not rewrite history or deploy latest.

Free-service idle spin-down and ephemeral storage remain. No guaranteed uptime, durable server backup, public model activation or physical-system safety claim is introduced by this fix.
