# Diagnostic transition and exit matrix

This maps the existing coupled-pump and retained-library engines to visible user states. It does not add a new diagnostic engine or alter verifier states. Four is the pump's maximum allowance; the library also preserves its declared `max_experiments` (1–4). All tests are synthetic.

| Reachable state / trigger | Primary action | Secondary / exit | Disabled action and explanation | Recovery / integrity rule |
|---|---|---|---|---|
| No active case / Cases directory | Select a synthetic pump scenario or library case | Resume the already visited workspace | No experiment without a captured case | The pump opens its documented normal default; the library needs explicit case creation |
| Case selected; simulation loading | Wait for bounded load | Existing view navigation | Playback/capture while busy | Failed load preserves the prior loaded case; retry initial simulation if none exists |
| Simulation ready / paused | Start or resume sampled playback | Inspect/focus component | Pause when already paused | Slider and camera do not recapture evidence |
| Simulation running | Pause / move recording position | Navigate another mode | Additional start while playing | Hidden document/workspace pauses playback; bounded cursor cannot pass recording end |
| Uninstrumented component | Select an instrumented component | Resume existing investigation | New capture; no mapped sensor | Selection does not replace the captured component/context |
| Observation window too short | Inspect diagnostic window / move through sample 319 | Resume existing capture | Capture before 319 | Existing reports stay accessible independently of playback cursor |
| Capture eligible | Capture selected component / observation window | Continue inspection | Capture with manual actions/imported source/counterfactual preview | Existing guards and backend validation apply; no model call |
| Capture request pending | Wait | View existing evidence | Additional captures/tests while busy | Bounded request; on interruption preserve report and restore before retrying a test |
| Evidence captured; hypotheses ready | Review competing explanations and proposed test | Export checkpoint | No automatic experiment | Rules/fixture source, missing evidence and contradictions remain labeled |
| Legacy observed; hypotheses not prepared | Prepare possible causes | Evidence / machine / checkpoint | No intervention before selection | Preparation and selection are separate existing optimistic-version actions |
| Experiment proposed / pending confirmation | Review predictions; explicitly run one test | Inspect evidence / report | Execution until selected; duplicate click guarded | Synchronous client latch plus existing backend version/store/work gates |
| Experiment executing / verification pending | Wait for one bounded response | Navigate without modifying evidence | New experiment while busy | Verification is computed server-side as part of that response, not a separate speculative UI result |
| Experiment completed; more evidence needed | Confirm the next eligible selected test | Inspect latest before/after | No automatic repeat | Earlier trial/event records are retained; no requirement to consume the allowance |
| Counterfactual playback | Resume existing investigation | Return to observed simulation | New capture/playback from outcomes | Resume is navigation only; return clears transient preview only |
| Returned to observed simulation | Resume or deliberately capture new evidence | Telemetry / machine | Capture if another original guard remains | Report, tests, cursor and recipe are unchanged by return |
| Supported terminal result | Review/export report | Machine / another case / save | No third test solely to reach four | Verifier reached support within synthetic assumptions; unused allowance shown as not needed under policy |
| Inconclusive terminal, unused allowance | Review ambiguity, contradictions and report | Start a different case or gather new independent evidence externally | No next test when selector has none | Unused budget is not proof another eligible test exists; do not call uncertainty a diagnosis |
| Inconclusive, budget exhausted | Review/export unresolved result | Another case / checkpoint | Extra tests beyond maximum | Completed/max/remaining and exhausted reason shown; partial findings are not complete support |
| Abstained / insufficient evidence | Inspect missing/invalid observations | Export or choose another case | Diagnostic execution without sufficient evidence | Preserve explicit abstention; do not invent missing readings |
| Rejected / inconsistent report state | Restore independently verified checkpoint or replay export | Evidence / another case | Execution of invalid/contradictory state | Presentation fails closed; imported reports still require full numerical reproduction |
| Report ready | Export JSON/HTML and recovery checkpoint | Return to machine / Cases | HTML export while pending | Export failures preserve report; stale asynchronous exports are discarded after case changes |
| Browser checkpoint pending | Explicitly restore | Export / discard / continue current case | Restore during an active operation | Stored candidate blocks default-boot replacement; credentials/private receipts excluded |
| Checkpoint file loading / reproducing | Wait for bounded backend reproduction | Current report remains visible | Duplicate imports/restores | File lock acquired before asynchronous read; stale workspace callback rejected before attachment |
| Investigation restored | Resume saved work / review final report | Machine / export | No extra trial simply because of recovery | Full report comparison, original trial history, remaining allowance preserved; transient playback resumes paused/observed |
| Legacy server session unavailable | Restore browser checkpoint into fresh temporary ID | New case / offline report replay | Advance missing server ID | Recompute existing fixed synthetic history; no future experiment, provider or source authentication |
| Storage denied/full/corrupt | Export validated public report/checkpoint where supported | Retry in available browser / keep current case | Save/restore if storage unavailable | Actionable sanitized error; no secret-bearing fallback storage |
| Backend unavailable / interrupted action | Reconnect or restore saved server/checkpoint state | Offline replay / retained exports | Blind retry of an uncertain test | Existing CAS/version protocol retained; boot/act generations reject stale responses; reconnect releases busy latch |
| Invalid telemetry/checkpoint/import | Correct bounded versioned input | Retain current report / export | Capture from imported replay | Reject malformed/schema/private/numerically altered data before applying it |
| Provider unavailable / activation blocked | Continue labeled deterministic investigation | Inspect recorded fixture provenance / Status | Genuine/public inference | Financial gate unchanged; zero genuine calls; no silent substitution |
| WebGL unavailable / reduced motion | Accessible 2D component controls and telemetry | Retry graphics / camera buttons | GPU-only interaction unavailable | No unavailable RPM or rotor motion invented; numerical engine is independent of graphics |

Across all modes, Cases exits to deliberate case selection; Machine and the inspector preserve the existing resume path. Telemetry explains observed/counterfactual/imported quality and missing/constant series. Investigation compares candidates, Experiments requires confirmation, Verification explains terminal policy, Reports exports, Evidence imports/prepares observed-only data, Replay inspects history, and Status/About discloses operational/model/storage limits. Navigation alone never executes a test.
