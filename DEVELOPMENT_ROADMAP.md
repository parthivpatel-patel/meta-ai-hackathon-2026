## Phase 0 — implemented foundation

FastAPI monolith, deterministic synthetic telemetry, statistical evidence, mock provider, disabled configurable Meta adapter, responsive fetched-data dashboard, tests, lockfiles, CI, and engineering documentation. This establishes a development baseline only.

## Phase 1 — verified numerical investigation loop

1. Define versioned hypothesis, experiment, observation, and verification records with explicit provenance, uncertainty, and contradiction fields.
2. Implement a small allowlisted experiment registry of pure numerical functions. Use bounded parameters and execution budgets; never execute model-generated code.
3. Hide simulation ground truth from inference; create competing mechanistic and sensor hypotheses. Choose experiments by expected discrimination.
4. Independently recompute test outcomes and accept, reject, or abstain based on declared criteria. Preserve contradictory evidence rather than forcing a diagnosis.
5. Add reproducible investigation exports with seeds, parameters, data hashes, calculation versions, model identity, prompts, and verification outcomes.
6. Extend evaluation across holdout seeds, missingness, confounders, and combined failures.

## Eligible Meta integration — required before submission

Verify official eligible model rules and obtain a free inference route without a payment method. Only then implement and separately authorize transport against an allowlisted endpoint. Preserve explicit mock/Meta status with no silent fallback, enforce usage bounds, and record provenance. This is a submission blocker until resolved; no eligible model has yet been used.

## Subsequent scope

Add documented multimodal inputs, persistent investigations, authentication, deployment hardening, report replay, operating-state transitions, validated physical models, and licensed independent datasets as time permits. Prioritize a convincing reproducible demonstration of tested hypotheses over breadth. Do not claim incomplete features in the submission or demo.
